# 파밍법 문장 기준

본문은 파밍법을 선택하고 준비·진행하는 사용자에게 필요한 안내로 쓴다. 조사자나 개발자가 수행한 작업을 보고하지 않는다.

- 요약: 파밍 대상과 핵심 방식. 미완성 구매 세팅은 요약에서도 한계를 밝힌다.
- 준비 조건: 무엇을 몇 개 준비하고 어떤 속성을 선택하는지. 필수·권장·대안을 구분한다.
- 진행 순서: 사용자가 수행할 동작을 순서대로 쓴다.
- 주의사항: 실패 조건, 패치 차이, 대안으로 바꿀 때 함께 변경할 조건.
- 제작자가 나중에 수정한 내용도 해당 준비 조건·진행 순서·주의사항에 직접 반영한다. 본문에 잘못된 안내와 정정문을 함께 두지 않는다. 고정 댓글 등의 근거는 해당 안내의 출처 링크로 남기고 변경 이력은 조사 문서에서 관리한다.
- 출처와 적용 범위: 출처 패치·날짜·연결 가이드·표본의 한계. 작업 과정은 조사 문서에서 관리한다.
- 미확인 사항: 아직 알 수 없는 조건을 명시한다. 보고체를 없애기 위해 추정치를 확정 사실로 바꾸지 않는다.

예: “의식 서판 2개를 확인했다” → “보류 단계에는 의식 서판 2개와 신념의 자유 1개를 사용한다.”

예: “최소값을 2로 수정했다” → “0.5.5 기준으로 안정화 후 희귀 몬스터를 2마리 추가하는 균열 서판을 구한다.”

기본 데이터는 생성 입력과 재생성 규칙에서 수정한다. 생성된 library.ko.json만 고치지 않는다. 문구를 다듬을 때 고정 ID·수치·선택 효과·출처 URL·타임스탬프·패치·검증 상태를 유지한다. 개인 수정본은 덮어쓰지 않는다.
