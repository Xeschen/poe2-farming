# 파밍 노트 사용성·UI 개선 요구사항

작성일: 2026-09-22  
대상: 로컬 웹앱 `http://127.0.0.1:4173/`  
목적: 다른 프로젝트 대화가 이전 대화를 읽지 않고도 평가 근거를 이해하고, 구현·검증·문서 수정을 이어가기 위한 인수인계 문서.

최신 재점검: [구현 후 재점검과 남은 개선사항](usability-recheck-2026-09-22.md). 앞선 구현의 검증 기록과 실제 시나리오 재평가를 구분하며, 새로 발견한 상세 진입 위치 오류와 잔여 UI 문제를 정리했다. 후속 구현으로 R-01~06을 반영했으며 최신 판단·검증은 재점검 문서 6절을 따른다.

## 1. 문서의 상태와 적용 범위

- 사용자는 파밍 실행, UI 적절성, 유튜브를 보며 개인 기록을 만드는 상황을 차례로 평가하도록 요청했고, 그 개선 요구사항을 프로젝트 문서로 남기도록 요청했다.
- 이 문서는 관찰 결과와 개선 제안을 정리한다. **앱 구현 완료 보고나 모든 제안의 최종 설계 승인 기록은 아니다.** 이 문서 작성 작업에서는 앱 코드·게임 데이터·개인 저장본을 수정하지 않았다.
- 우선순위는 평가자의 제안이다. 사용자의 후속 구현 지시와 최신 작업 상태를 우선하며, 구현 전에 해당 현상을 다시 확인한다.
- 기존 [프로젝트 지침](../AGENTS.md), [제품 계획](product-plan.md), [데이터 계약](data-schema.md)을 함께 읽는다. 첫 시제품의 저장·복원·데이터 분리 기준을 유지한다.
- 아래의 관찰은 UI와 입력 흐름에 대한 것이다. 현재 게임 메타·시세·실전 수익·전체 아틀라스 경로를 검증한 결과가 아니다.

### 기존 결정과 충돌하거나 해석을 주의할 부분

1. **출처 편집 재도입:** 제품 계획과 [편집기 기록](editor-validation.md)의 마지막 변경은 영상 출처·타임스탬프 편집을 의도적으로 제거하고 기존 근거를 보존한다. 아래 `AUTHOR-01/03`은 유튜브 개인 정리 시나리오에서 제안한 범위 변경이다. 과거 제거를 단순 버그로 취급하거나 모든 세팅 영역에 복잡한 출처 폼을 무조건 복원하지 않는다. 구현 범위에 포함되면 관련 계획·검증 기대값을 함께 갱신한다.
2. **자동 임시저장과 명시적 저장:** 기존 결정은 저장 버튼을 누르기 전 정상 저장본을 바꾸지 않는 것이다. `AUTHOR-06`은 별도 임시 초안의 복구를 제안한다. 기존 세팅의 자동 덮어쓰기를 되살리는 요구가 아니다.
3. **기존 타이포그래피:** [글자 체계](ui-typography.md)는 수량·수치를 강조하도록 변경한 기록이다. 이번 제안은 이를 무조건 작게 되돌리는 것이 아니라, 필수 옵션·선택 효과·실행 판단과 균형을 맞추자는 것이다.
4. **여러 줄 붙여넣기는 이미 지원:** 이전 대화에서는 조작이 눈에 띄지 않는다고 평가했다. 문서 작성 중 `src/app.js`의 paste 처리와 `tests/editor-browser.mjs`에서 줄 단위 분리 구현·검증 코드를 확인했다. 기능 부재로 기록하지 않는다. 안내와 발견 가능성 개선 및 회귀 검증 대상이다.
5. **미확인 값의 의미는 필드별 계약을 따른다:** 모든 빈 값에 같은 의미를 부여하지 않는다. 기존 계약에는 미확인 수치와 검색 범위 제한 없음이 각각 존재한다. 새 상태를 추가할 때 이전 형식의 의미를 보존한다.

## 2. 사용자 시나리오

### A. 파밍을 선택해 게임을 진행

가정: 기본적인 지도 진행이 가능하고, 솔로로 약 1시간 플레이하며 처음부터 큰 비용을 쓰고 싶지 않은 사용자. 모든 플레이어를 대표하는 통계가 아닌 평가용 가정이다.

| 단계 | 사용자의 질문·행동 | 필요한 지원 |
|---|---|---|
| 탐색 | 내 자본·캐릭터로 무엇을 할 수 있나? | 준비 부담, 캐릭터 요구, 진입 조건, 현재 확인 범위 |
| 비교 | 후보 2~3개 중 무엇이 적합한가? | 의사결정에 필요한 차이를 먼저 비교 |
| 준비 | 무엇을 사서 어떻게 설정하나? | 역할별 준비물, 옵션, 구매 연결, 설정 체크리스트 |
| 실행 | 지금 다음에 무엇을 해야 하나? | 짧은 진행 화면, 현재 단계, 주의·중단 조건 |
| 평가 | 몇 판 해 보니 계속할 만한가? | 비용·판매 수입·미판매 전리품·사망·메모 기록 |
| 재방문 | 지난번 세팅과 진행을 이어가고 싶다 | 최근 기록·선택한 전략·메모에 빠른 접근 |

### B. 유튜브 파밍 소개를 보며 개인적으로 정리

영상 URL 보관 → 시간과 함께 빠른 메모 → 모르는 내용 보류 → 서판·경로석·아틀라스 등으로 정리 → 원본 구간 재확인 → 개인 기록 저장 → 나중에 재방문.

영상의 설명 순서는 앱의 세팅 항목 순서와 다를 수 있다. 시청 중에는 내용을 놓치지 않는 것이 우선이고, 공식 명칭·옵션으로 구조화하는 작업은 이후에도 할 수 있어야 한다.

## 5. 데이터 표시와 파밍 실행 요구사항

### DATA-01 — 미확인과 제한 없음의 일치

- 관찰: OBS-08. 특정 옵션이 필요 없다는 안내와 옵션을 확인하지 못했다는 안내는 구매 판단이 다르다.
- 요구: 카드·상세·비교·편집·거래소에서 같은 의미를 일관되게 표시한다. 빈 옵션 배열만으로 ‘제한 없음’을 추정하지 않는다.
- 완료 기준: 근거가 있는 제한 없음은 명시적으로 표시하고, 실제 미확인 기록은 계속 미확인이다. 기존 백업을 복원해도 둘을 임의 변환하지 않는다. 원본 생성 입력과 출력이 재생성 후에도 일치한다.

### DATA-02 — 문맥에 맞는 용어 연결

- 관찰: OBS-09.
- 요구: 문장 일부와 사전 이름이 일치한다는 이유만으로 다른 의미의 용어를 연결하지 않는다. 공식 ID 참조 또는 문맥·용어 경계를 고려하고, 불확실하면 연결을 생략한다.
- 완료 기준: 심연 관련 문장의 ‘구덩이’에 지도 지역 카드가 나오지 않는다. 실제 지도 지역 참조와 기존 정확한 용어 설명은 유지된다. 관련 명칭은 PoEDB 한국어로 대조한다.

### PLAY-01 — 실행 가능성 판단 요약

- 관찰: OBS-01.
- 요구: 목적·확인 범위와 함께 캐릭터 요구 수준, 필수 해금·준비 조건, 준비 부담, 솔로 적합성, 보상의 성격·편차를 근거가 있는 범위에서 요약한다. 기존 필터에 추가할 항목은 데이터 확보 후 결정한다.
- 완료 기준: 사용자가 시작 전에 확인할 필수 조건과 미확인 사항을 구분할 수 있다. 비용은 기준·화폐·출처 시점을 보존하며, 영상의 ‘낮음’을 임의 금액으로 바꾸지 않는다. 미확인 데이터로 추천 점수나 순이익 순위를 만들지 않는다.

### PLAY-02 — 준비·구매·설정 체크리스트

- 관찰: OBS-10.
- 요구: 같은 서판이라도 필수 옵션·역할을 구분하고 총수량과 각 구성의 의미를 요약한다. 구매·준비·설정 완료를 표시한다. 대안 선택 시 함께 변경할 아틀라스·대가 조건을 연결해 보여 준다.
- 완료 기준: 사용자가 각 준비물을 확인하고 남은 항목을 알 수 있다. 기존 옵션·거래소 연결과 필수·선택·대안 구분을 보존한다. 체크 상태는 기본 자료·세팅 내용과 분리하며 세팅 변경 시 낡은 완료 상태를 그대로 신뢰시키지 않는다. 대안의 종속 변경은 근거가 있을 때만 안내한다.

### PLAY-03 — 게임 중 짧은 진행 화면

- 요구: 입장 전 확인 → 지역 안 행동 → 보상 회수 → 다음 판의 실행 흐름, 현재 단계, 핵심 주의·중단 조건을 짧게 표시한다. 자세한 근거는 펼쳐 읽는다.
- 완료 기준: 목록·출처 전문을 다시 지나지 않고 진행 화면에 접근한다. 모바일·키보드에서도 단계 표시와 초기화가 가능하다. 선택 전략과 현재 위치가 명확하다. 원본에 없는 행동이나 중단 수치를 임의 작성하지 않는다.

### PLAY-04 — 빠른 메모와 판별 기록

- 요구: 상세에서 전체 편집기를 열지 않고 한 줄 메모나 한 판 결과를 기록한다. 비용, 실제 판매 수입, 미판매 전리품, 사망·소요 시간 등을 필요한 범위에서 분리한다.
- 완료 기준: 세팅 변경과 플레이 기록이 분리된다. 미판매 추정 가치를 실현 수익으로 합산하지 않는다. 미기록과 0을 구분한다. 기록은 개인 저장·백업에만 포함하고 공개 배포에 섞이지 않는다.
- 범위 조정: 간단한 메모를 먼저 구현하고, 수익 집계·회차 관리의 상세 설계는 후속 범위로 나눌 수 있다.

## 6. UI·시선 동선 요구사항

### UI-01 — 중복 목록 제거와 본문 우선 배치

- 관찰: OBS-02/07.
- 요구: 라이브러리는 필터와 단일 결과 목록으로 구성한다. 상세·비교·작성 중에는 전체 목록을 접거나 ‘파밍법 바꾸기’로 접근한다. 좁은 화면에서 선택한 전략보다 전체 목록을 먼저 길게 표시하지 않는다.
- 완료 기준: 390px 상세·비교 직접 진입 시 선택한 전략·현재 화면 제목이 첫 화면에 보인다. 960px에서는 본문을 읽거나 작성하는 공간이 우선이다. 필터·선택 전략·뒤로 가기 상태를 잃지 않는다.

### UI-02 — 공간 배분과 컴포넌트 크기

- 관찰: OBS-02/03/05/06.
- 요구: 제목·소개·영문 장식·여백을 압축하고 세팅을 위로 당긴다. 카드 항목 위치를 통일하고 긴 설명은 요약한다. 미확인만 나열하는 큰 패널은 간결하게 표현한다. 고정 비교 바는 한 줄 중심으로 줄이고 상세 선택 목록은 펼친다.
- 설계 참고: 목록 카드 높이 200~260px는 초기 검토안이지 강제 기준이 아니다. 글자를 줄여 맞추거나 중요한 조건을 잘라내지 않는다.
- 완료 기준: 대표 상세의 1265×720 첫 화면에서 최소 한 준비 항목의 내용을 확인할 수 있다. 카드의 비교 선택이 과도한 여백 때문에 밀리지 않는다. 비교 화면에서 중복 실행 버튼을 없애고, 고정 바가 마지막 콘텐츠·포커스·모바일 키보드 조작을 가리지 않는다.

### UI-03 — 상세 읽기 순서와 정보 위계

- 관찰: OBS-03/05.
- 요구: 전략 요약 다음의 세팅 순서를 등록과 열람 모두 서판 → 경로석·지도 → 아틀라스·대가 → 진행·주의점으로 통일한다. 최초의 아틀라스 우선 후보는 등록·열람 일관성에 대한 사용자 결정으로 대체했다. 오른쪽에는 긴 필수 설정 대신 짧은 목차를 두고 현재 구역을 표시한다.
- 요구: 옵션 조건·선택 효과·주의사항을 수량과 함께 쉽게 찾게 한다. 미확인은 중요한 확인 필요 여부를 전달하되 모든 큰 수치 카드의 주인공이 되지 않도록 한다.
- 완료 기준: 종속된 설정을 불필요하게 좌우 왕복하지 않고 읽는다. 시각 순서·DOM·키보드 순서가 일치하고 목차 이동 후 위치를 잃지 않는다. 미검증 안내와 서로 다른 희귀도·수량·출현 확률 필드는 유지한다.

### UI-04 — 비교의 요약·세부 분리

- 요구: 비용·필수 준비물·진입 조건·위험·검증 상태의 차이를 먼저 보여 주고, 긴 옵션·근거는 펼쳐 본다. 기존 ‘차이만 보기’를 유지한다. 작은 화면에서는 같은 비교 항목의 값을 가까이 배치하는 방식을 검토한다.
- 완료 기준: 전략 이름과 비교 항목의 관계를 스크롤 중에도 파악할 수 있다. 요약과 세부 내용의 의미가 일치하며, 미확인과 제한 없음의 차이를 숨기지 않는다. 2개·3개 비교와 개인/기본 혼합 비교가 모두 유지된다.

### UI-05 — 조작·보조 정보·설명 카드

- 관찰: OBS-04/09.
- 요구: 현재의 약 44px 주요 버튼과 16px 본문을 출발점으로 유지한다. 필수·선택·미확인은 색만으로 구분하지 않는다. JSON 백업·공유·복사·비교의 강조를 화면의 주 행동에 맞게 조정한다. 백업은 ‘데이터 관리’로 묶는 방식을 검토한다.
- 요구: 모바일 설명 카드는 누른 문장을 가리지 않는 인라인 확장 또는 하단 패널을 검토한다. 메뉴처럼 보이는 장식은 기능과 혼동하지 않게 한다.
- 완료 기준: 글자·포커스·보조 정보의 대비를 실제 검사한다. 설명을 마우스·터치·키보드로 열고 닫고 출처로 이동할 수 있다. 닫기 후 원래 위치로 돌아온다. 데이터 관리 진입이 숨겨져 백업을 찾기 어려워지지 않는다.

## 7. 유튜브 개인 정리 요구사항

### AUTHOR-01 — 영상 URL로 기록 시작

- 관찰: OBS-11. 기존 출처 입력 제거 결정과 구분해야 하는 범위 변경 제안이다.
- 요구: 최소 제목·영상 URL·빠른 메모로 개인 기록을 시작한다. 필요한 경우 제작자·출처 패치·확인 상태를 추가하되 모르는 값을 강제 입력시키지 않는다.
- 완료 기준: 새 개인 기록에서 등록한 영상이 상세와 백업·복원에 남고 다시 열 수 있다. 기존 기본 자료의 출처·근거는 변하지 않는다. URL을 검증하고 임의 HTML을 실행하지 않는다. 외부 메타데이터 자동 추출은 필수 조건이 아니다.

### AUTHOR-02 — 메모 후 구조화

- 요구: 넓은 빠른 메모를 상단에서 제공하고, 시청 순서대로 적은 내용을 나중에 준비물·옵션·진행 순서로 옮기거나 연결한다. ‘영상 보며 메모’와 ‘세팅 정리’의 전환을 검토한다.
- 완료 기준: 숫자·공식 명칭을 아직 몰라도 원문 메모를 보관할 수 있다. 구조화 전후에 원문이 유실되지 않고 임시 문구가 확인된 공식 데이터로 취급되지 않는다. 최소 기록을 위해 모든 상세 세팅을 채울 필요가 없다.

### AUTHOR-03 — 타임스탬프와 근거 연결

- 관찰: OBS-12. 단순 시간 텍스트를 적어도 영상 근거로 연결되지 않았다.
- 요구: 영상·시간·메모·관련 세팅 항목을 연결한다. `mm:ss` 또는 `hh:mm:ss` 직접 입력을 우선 지원할 수 있다. 영상 재생 위치 자동 읽기는 필수가 아니다.
- 완료 기준: 연결을 누르면 올바른 영상의 해당 구간을 연다. 여러 영상의 근거가 섞이지 않고, 잘못된 시간·영상 ID는 오류로 안내한다. 개인 복사·편집·백업·복원에서 기존/추가 근거 모두 보존한다.

### AUTHOR-04 — 검색형 선택과 임시 문구 보존

- 요구: 서판·옵션·아틀라스 선택에 키워드 검색을 제공한다. 공통·해당 종류 전용 옵션을 구분한다. 들은 이름이 불명확하면 ‘명칭 재확인’ 메모로 남긴 뒤 공식 ID에 연결한다.
- 완료 기준: 부분 검색·키보드 선택이 가능하고 검색어 변경으로 기존 선택이 유실되지 않는다. 등록되지 않은 임시 문구를 공식 명칭으로 표시하거나 거래소 옵션으로 변환하지 않는다. 기존 선택형 검증을 우회하지 않는다.

### AUTHOR-05 — 메모 성격과 연속 입력

- 요구: 영상 설명 / 내 해석 / 직접 해 본 결과 / 재확인 필요를 구분할 수 있다. 항목 입력·삭제·순서 재배치에서 포커스와 스크롤을 유지한다.
- 기존 지원: Enter 추가 후 연속 입력과 여러 줄 붙여넣기 분리는 유지한다. 붙여넣기 기능은 짧은 도움말로 발견 가능성을 높인다. 순서 재배치는 구현 여부를 재확인하고 없으면 마우스와 키보드 모두 가능한 방식으로 추가한다.
- 완료 기준: 원문·근거·개인 해석이 섞이지 않는다. 재배치 후 연결된 출처가 다른 항목으로 옮겨 붙지 않는다. 항목 ID 등 안정적인 연결 설계를 검토한다. ‘직접 해 봄’ 표시가 현재 패치 전체 검증이나 확정 수익을 뜻하지 않는다.

### AUTHOR-06 — 별도 초안 복구와 재방문

- 요구: 작성 중 초안은 별도 로컬 임시 영역에 저장하고 복구·폐기할 수 있게 한다. 정리 중/완료, 다시 볼 구간, 마지막 기록 위치를 필요한 범위에서 보관한다.
- 완료 기준: 명시적 저장 전 정상 records는 바뀌지 않는다. 취소한 초안이 다시 자동 복구되지 않는다. 새 기록·기존 기록·복사본의 초안이 구분된다. 저장 실패·용량 초과·다른 탭 변경 시 입력과 정상본을 보호한다. 공유 URL·공개 빌드에 초안이 들어가지 않는다.
- 백업 기준: 현행 JSON 내보내기는 정상 저장 records만 대상으로 유지한다. 초안 내보내기까지 필요해지면 사용자에게 명확히 구분되는 별도 설계를 적용한다.

### AUTHOR-07 — 작성 화면과 미리보기

- 관찰: OBS-11/13.
- 요구: 작성 중 다른 전략 목록을 접고 영상·메모·현재 입력 구역에 공간을 할당한다. 빠른 메모를 항상 쉽게 열 수 있게 하고, 목차를 단순화한다. 미리보기는 입력 아래에 계속 쌓기보다 같은 항목 위치를 유지하며 전환하는 방식을 검토한다.
- 완료 기준: 960px 폭에서 영상을 다른 창에 두고도 입력 내용·현재 구역·저장 상태를 쉽게 찾는다. 메모 상자의 초기 94px 높이를 주 작성 영역에 맞게 개선한다. 편집/미리보기 전환, 구역 이동, 좁은 화면에서도 미저장 입력과 포커스가 보존된다.

## 8. 권장 구현 묶음과 의존 관계

사용자의 후속 구현 지시에 맞춰 묶음을 선택한다. 모든 요구를 한 번에 개발하거나 이 문서 작성만으로 배포를 시작하지 않는다.

1. **정확한 표시:** DATA-01/02. 관련 데이터·렌더링과 근거를 먼저 대조한다.
2. **공통 화면 정리:** UI-01/02/03/05, AUTHOR-07. 목록·상세·편집 공간과 모바일 본문 접근을 개선한다.
3. **영상 개인 기록:** AUTHOR-01/02/03을 중심으로 데이터 계약·원본 보존·기존 테스트 기대값을 함께 정리한다. AUTHOR-04/05/06을 후속으로 연결한다.
4. **실전 준비·진행:** PLAY-01/02/03, UI-04. 체크 상태는 콘텐츠와 분리하고, 근거가 없는 게임 조건을 UI 작업으로 채우지 않는다.
5. **플레이 기록 확장:** PLAY-04. 빠른 메모부터 시작하고 필요할 때 판별 집계를 확장한다.

정적 앱·무료 운영·GitHub Pages 하위 경로·기기 간 JSON 이동 원칙을 유지한다. 자동 시세 조회, AI 영상 요약, 로그인·클라우드 동기화, 유료 API는 이번 요구를 구현하기 위한 필수 조건이 아니다.

- 정적 빌드와 /dist/ 하위 경로에서 usability-browser, browser, editor-browser 검증 완료. 외부 거래소 결과·게임 실전은 이번 검증 범위가 아니다.

### 2026-09-22 R-01~06 후속 반영

수정된 문서의 여섯 항목을 채택했다. R-01은 탐색 오류 수정, R-02~05는 표시·작성 동선 개선, R-06은 사용자가 반복 확인 항목과 시작 단계를 정하는 방식이다. 새로 발견한 문제와 기존에 보류한 기능을 구분했다. 구현 판단과 최신 검증은 [재점검 문서 6절](usability-recheck-2026-09-22.md#6-r-01r-06-후속-구현과-검증)을 따른다. 개인 백업 v6·기본 데이터·게임 명칭·출처는 변경하지 않았다.
