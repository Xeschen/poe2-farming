## 3. 남은 개선사항

### R-01 · P1 · 목록에서 상세 진입 시 스크롤 위치 초기화

- 관련 요구: UI-01/03. **실제로 재현한 동작 오류**다.
- 재현: 라이브러리에서 아래쪽 ‘심연 화폐 파밍’ 제목을 눌러 상세를 연다.
- 실제: 목록에서 내려간 스크롤이 남아 아틀라스·대가 영역 중간이 보인다. 제목의 뷰포트 y좌표는 약 -859px였다. 다른 도구 호출 뒤 다시 확인해도 유지되어 단순 전환 애니메이션 중간 캡처가 아니었다.
- 영향: 무엇을 열었는지 바로 확인하기 어렵고, 제목·요약·‘준비·진행 시작’ 버튼을 찾으려면 위로 돌아가야 한다.
- 코드 근거: `src/app.js`의 `data-select` 처리(점검 시 432행)는 렌더링과 main 포커스만 수행한다. `navigatePage` 및 준비/진행 전환에는 별도의 스크롤 초기화가 있다.
- 개선: 새 전략 선택은 상세 시작점으로 이동한다. 브라우저 뒤로 가기로 목록에 복귀할 때는 필터·선택·기존 목록 위치를 복원하도록 구분한다. 편집기 내부 재렌더의 위치 보존과 혼동하지 않는다.
- 완료 기준: 목록 하단·검색 결과·파밍법 전환창·비교 상세 버튼에서 새 전략 진입 시 제목과 주 행동을 볼 수 있다. 뒤로 가기와 앵커 이동의 의도된 위치는 보존된다.
- 검증 보완: 기존 `usability-browser`의 초기 진입 검사는 상세 URL 직접 열기 중심이다. ‘목록을 내린 뒤 카드 클릭’ 및 ‘긴 비교표에서 상세 클릭’ 경로를 추가한다.

### R-02 · P1 · 준비 목록에서 옵션 역할을 펼치기 전에 표시

- 관련 요구: PLAY-02/03.
- 실제: 세 서판의 체크 제목은 ‘서판 1/2/3 · 심연 서판 · 1개 · 필수’이고 핵심 차이는 각 ‘조건 보기’ 안에 있다. 세 옵션을 비교하려면 각각 펼쳐야 한다.
- 추가 관찰: 개별 서판 3개와 별도로 ‘심연 서판 3개’라는 준비물 체크가 있어 의미가 겹친다. 경로석도 조건 확인과 준비물 설명이 따로 체크 항목으로 잡힌다.
- 개선: 체크 제목 아래에 역할·필수 옵션을 한 줄로 노출한다. 세부 수치·근거는 접을 수 있다. 구조화된 준비물과 설명용 준비물이 같은 대상을 가리키면 중복 체크 대신 관련 설명으로 연결한다. 단순 문자열 유사성만으로 중요한 준비물을 삭제하지 않는다.
- 완료 기준: 펼치지 않아도 각 서판이 왜 다른지 판단할 수 있고, 같은 준비를 두 번 완료해야 하는 것처럼 보이지 않는다. 대안 구성과 원본 옵션·거래소 조건을 보존한다.

### R-03 · P2 · 요약 비교의 긴 설명 분리와 모바일 비교 동선

- 관련 요구: UI-02/04.
- 실제: 요약 모드의 서판 구성 행에 힐다 대안 등 여러 문단이 그대로 들어간다. 두 전략 요약 표가 데스크톱 약 1575px, 모바일 높이 약 1917px/폭 690px였다. 390px 첫 화면에서는 첫 번째 전략만 보여 두 번째와 읽어 비교하려면 가로 이동이 필요하다.
- 개선: 요약 행에는 구성·핵심 차이·주의 여부를 짧게 표시하고 대안 전문·근거는 별도 펼침으로 이동한다. 모바일에는 비교 항목별 두 전략 값을 세로로 묶는 보기 등을 검토한다. 비용·검증 안내를 삭제하지 말고 짧은 안내와 상세 설명으로 나눈다.
- 완료 기준: 선택한 두 전략의 같은 항목을 번갈아 기억하지 않고 읽을 수 있다. 3개 비교에서도 전략 이름이 명확하며, 미확인/제한 없음·대안 주의점이 누락되지 않는다.

### R-04 · P2 · 작성 첫 화면의 상단 압축

- 관련 요구: UI-02, AUTHOR-02/07.
- 실제: 메모가 상단으로 이동했지만 960×720에서 입력칸 시작이 y≈497px였다. 화면 제목·일반 저장 설명·버튼 행·‘새 파밍법’ 제목·긴 상태 설명이 앞에 놓인다. 메모 구조화 버튼은 더 아래에 있다.
- 개선: 상단에 기록 이름·저장 상태·저장/취소를 간결하게 묶고, 상세 입력 규칙은 필요할 때 확인하게 한다. 빠른 메모와 구조화 행동이 첫 화면의 주 영역이 되게 한다. 처음 입력할 때 기본 이름 ‘새 파밍법’을 쉽게 바꿀 수 있도록 한다.
- 완료 기준: 960×720에서 충분한 메모 영역과 최소 하나의 구조화 행동을 함께 볼 수 있다. 입력 규칙·미저장 상태·오류는 여전히 명확하며, 글자/버튼을 지나치게 줄여 공간을 확보하지 않는다.

### R-05 · P2 · 메모만 있는 초안에 맞는 미리보기

- 관련 요구: AUTHOR-02/07, UI-02.
- 실제: 메모와 준비물 두 항목만 작성한 상태에서도 미리보기는 목적·비용·아틀라스·대가·경로석 등의 ‘미확인’을 먼저 보여 준다. 실제 작성한 메모는 아래쪽에 있어 모바일에서는 여러 패널을 지나야 한다. 모달 전환·Esc·입력 보존 자체는 정상이다.
- 개선: ‘작성한 항목만 보기’ 또는 현재 편집 구역과 대응하는 미리보기 위치를 제공한다. 필요한 미확인 조건은 요약으로 남기고 전체 세팅 보기에서 다시 확인할 수 있게 한다.
- 완료 기준: 메모 또는 준비물 확인을 위해 미리보기를 열었을 때 해당 내용을 쉽게 찾는다. 빈 영역을 감추는 것이 미확인 세팅을 완성된 세팅으로 오인시키지 않는다. 미리보기 종료 시 입력·커서·스크롤을 보존한다.

### R-06 · P2 · 다음 판에서 유지할 준비와 다시 확인할 준비 구분

- 관련 요구: PLAY-02/03. **현재 명세를 위반한 오류로 단정하지 않는 UX 제안**이다.
- 실제: ‘다음 판 · 진행 초기화’는 2/3 단계를 1/3으로 돌리고 준비 체크 1/8은 유지한다. 문구대로 단계만 초기화된다.
- 문제: 지속 설정과 판마다 준비할 수 있는 소모품이 한 체크 목록에 있어 어떤 체크가 계속 유효한지 판단을 사용자에게 맡긴다. 첫 단계 자체도 ‘서판 준비’여서 준비 영역과 중복된다.
- 개선: 지속 설정/이번 판 준비를 구분하고 다음 판의 초기화 대상을 명시한다. 게임 규칙이 확인되지 않은 항목을 임의로 소모품 분류하지 않는다. 원본 단계는 보존하면서 준비와 반복 행동의 위치를 조정한다.
- 완료 기준: 사용자가 다음 판에서 다시 확인할 항목을 알 수 있고, 지속 설정을 매번 불필요하게 다시 체크하지 않는다. 현재 세팅의 변경 시 초기화와 혼동하지 않는다.

## 6. R-01~R-06 후속 구현과 검증

수정된 문서를 다시 읽고 여섯 항목 모두 채택했다. R-01은 동작 오류로 수정하고, R-02~05는 관찰된 읽기·작성 부담을 줄였다. R-06은 게임 규칙을 추정하는 자동 분류 대신 사용자 지정 방식을 적용했다.

| 항목 | 판단·최종 동작 |
|---|---|
| R-01 | 새 파밍법을 선택하면 제목과 주 행동이 있는 상세 시작점으로 이동한다. 브라우저 기록에 문서·비교표 스크롤을 보관하고 뒤로 가기 시 검색·필터와 함께 복원한다. 편집기 내부 재렌더·목차 이동은 기존 위치 정책을 유지한다. |
| R-02 | 준비 목록을 처음부터 보여주고 서판별 필수/회피 옵션 또는 제한 없음·미확인 상태를 체크 제목 아래 표시한다. 검토한 기존 준비물 문장은 정확히 일치할 때만 서판 전체/경로석 설명으로 연결한다. 임의 수정 문장·낯선 준비물은 별도 체크로 남기며, 구조화된 서판이 없으면 원문도 체크로 남는다. 원문·대안·전체 옵션·거래소 조건은 삭제하지 않는다. |
| R-03 | 요약에 서판 구성과 대표 옵션을 표시하고 대안 전문·추가 조건·주의·출처는 펼침으로 분리한다. 긴 대표 옵션은 말줄임을 표시하고 전체 옵션에서 읽을 수 있다. 제한 없음과 미확인은 계속 구별한다. 700px 이하에서는 비교 항목마다 2~3개 파밍법 이름과 값을 세로로 묶어 가로 이동 없이 대조한다. 상세 조건·차이만 보기·비용/검증 안내도 유지한다. |
| R-04 | 중복 제목과 저장 설명을 줄이고 입력 규칙을 접었다. 이름은 빠른 메모 바로 위에서 바꾸며 새 기록은 기본 이름을 선택한 상태로 시작한다. 저장 상태·오류·상단/목차/하단 저장·취소는 유지한다. 960×720에서 메모 220px와 첫 구조화 버튼 전체를 함께 확인했다. |
| R-05 | 기본 미리보기는 입력이 있는 영역을 보여주며 메모/준비·진행 버튼은 해당 내용을 먼저 보여준다. 메모를 복사한 뒤 ‘복사한 내용 확인’으로 목적 영역을 볼 수 있다. 미확인 요약·완성 여부 안내와 전체 세팅 보기를 제공한다. 닫을 때 원래 편집 DOM·입력·선택 범위·스크롤·포커스를 유지한다. |
| R-06 | ‘유지할 준비’와 ‘이번 판 준비’를 나눴다. 사용자가 ‘다음 판 다시 확인’을 선택한 항목만 다음 판에서 체크 해제한다. 다음 판 시작 단계를 지정해 이미 끝낸 준비 단계를 건너뛸 수 있고 원본 단계는 그대로 남긴다. 초기화 대상 수와 시작 단계를 버튼 아래 명시한다. 설정 변경 시 전체 초기화와 구분하며 모든 진행 설정은 탭 메모리 전용이다. |

### 이번 구현의 검증

- 단위 테스트 **77개 통과**. 준비물 원문 보존·수정 문장의 독립 체크 유지·서판 역할 구분·사용자 지정 초기화·전략 간 상태 분리·세팅 변경 초기화를 추가했다. 기존 백업/검증/데이터 분리 테스트를 유지한다.
- `recheck-browser`: 1265×720, 960×720, 390×844, 320×844. 목록 하단·검색 결과·전환창·긴 비교 화면에서 실제 상세 버튼 클릭, 뒤로 가기의 필터/위치 복원, 3개 비교의 항목별 세로 배치, 역할 상시 표시, 유지 체크와 판별 체크 분리, 새로고침 초기화, 작성 첫 화면, 부분/전체 미리보기, 취소·커서/스크롤 보존을 확인했다.
- `usability-browser`, `catalog-browser`, `browser`, `editor-environments-browser` 통과. 11종 기본 자료 상세·복사·편집, 출처 보존, 개인 자료/기본 자료 분리, 백업·복원, 입력 실패·저장 용량·다중 탭 보호, 키보드 설명/모바일 터치, 환경 선택과 저장·취소를 회귀 확인했다. 모바일 비교의 과거 ‘가로 스크롤 필수’ 기대값은 이름이 붙은 세로 비교 기준으로 갱신했다.
- 정적 빌드 완료. `/dist/` 하위 경로에서도 최신 `recheck-browser` 전체 흐름을 통과했다.
- 960×720 새 편집 화면: 메모 시작 y≈415px, 높이 220px, 첫 구조화 버튼 하단 y≈703px. 이는 해당 브라우저의 대표 측정값이며 모든 환경의 고정 치수 계약이 아니다.
- 편집·비교·준비·메모 미리보기 화면을 캡처해 확인했다. 모바일 세로 비교는 세로 길이가 늘어나는 대신 항목별 값을 한 화면 폭에서 읽도록 선택했다. 전체 접근성 인증·외부 거래소 실검색·현재 시세·게임 실전 검증은 아니다.

기본 게임 데이터, 개인 백업 v6, 영상 근거와 공식 명칭은 변경하지 않았다. 4절의 영상 입력·복구 초안·판별 수익 기록 등 보류 범위는 그대로 남는다.

### 후속 결정: 등록·열람 순서 통일

사용자 요청에 따라 세팅 본문과 목차, 전체 미리보기의 순서를 **서판 → 경로석·지도 → 아틀라스·대가 → 진행·주의점 → 출처**로 맞췄다. 등록 화면의 세팅 순서는 이미 같아 유지한다. 메모·준비물 확인 버튼으로 여는 부분 미리보기는 선택한 내용을 먼저 보여주는 기존 기능을 유지한다. 앞 절의 아틀라스 우선 배치는 당시 구현 기록이며 현재 기준이 아니다.

### 후속 결정: 열람 단락 접기

열람 본문의 각 단락과 개인 메모에 기본적으로 열린 `details`를 적용했다. 제목 행 전체를 눌러 접고 펼치며, 키보드 Enter·Space도 지원한다. 목차로 이동하면 대상 단락을 먼저 펼친다. 내부 근거 펼치기는 별도로 유지하고 편집·미리보기의 기존 구조는 유지한다. 새로 열거나 새로고침하면 모두 펼쳐진다. 1265/390/320px에서 개별 접기, 목차 이동, 개인 메모와 가로 넘침을 점검했고 기존 사용성 브라우저 검증도 통과했다.
