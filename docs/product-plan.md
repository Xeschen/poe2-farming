# 제품 계획

## 목표

파밍법을 조건별로 찾고, 준비물을 비교하고, 실제 세팅을 따라 하며, 자신의 변형을 보관할 수 있는 웹앱.

## 데이터 설계

하나의 항목은 하나의 재현 가능한 세팅이다. 준비물이 크게 다른 저투자·고투자 방식은 분리한다.

필드: 이름, 목적, 콘텐츠, 적용 패치, 준비 조건, 서판과 개수·속성, 경로석 등급·속성, 지도 지역·환경, 아틀라스 노드·선택 효과, 대가, 준비물, 진행 순서, 중단 조건, 출처, 정정, 확인 상태.

기본 데이터는 저장소의 JSON으로 관리한다. 개인 수정본에는 자체 ID와 원본 ID·복사 당시 버전을 두어 원본 업데이트를 감지할 수 있게 한다. 기본 데이터 업데이트가 개인 변경을 덮어쓰지 않는다. 정확한 새 스키마는 첫 구현 전에 확정한다.

## 용어 설명

- 공식 한국어 명칭, 분류, 효과 요약, 선택 효과, 확인한 패치, PoEDB URL을 관리한다.
- 밑줄 용어에 마우스를 올리거나 키보드 포커스를 주면 설명 카드를 표시한다.
- 클릭 시 PoEDB 한국어 페이지를 새 탭으로 연다.
- 모바일에서는 터치로 설명을 열고 카드 안에 별도 이동 링크를 제공한다.
- 해당 파밍법에서 선택한 효과를 카드에 강조한다.
- 검색 별칭은 지원할 수 있으나 표시 이름은 공식 명칭이다.
- 초기 명칭 사전은 이름과 URL 위주이므로 설명 보강이 필요하다.

## 화면

1. 목록: 파밍법, 목적, 서판 조합, 투자 수준, 대가, 패치, 확인 상태.
2. 상세: 준비물, 세팅, 진행 순서, 주의점, 출처.
3. 편집: 서판·속성 행 추가, 용어 자동완성, 필수·권장·회피·미확인, 타임스탬프, 미리보기.
4. 비교: 2~3개 항목의 준비 조건과 차이. 첫 시제품 다음 단계.

## 개인 데이터

기본 파밍법의 '내 데이터로 복사'와 직접 추가를 지원한다. 브라우저 안에서 자동 저장하며, JSON 내보내기·가져오기와 복원 전 검증을 제공한다. 브라우저 저장은 디스크의 JSON 파일 갱신과 다르다는 점을 설명한다. 첫 버전에는 기기 간 자동 동기화가 없다.

공개 데이터 업데이트는 편집 → JSON 내보내기 → 저장소 변경 검토 → 배포 순서다. 초기에는 브라우저에 GitHub 쓰기 권한이나 개인 토큰을 넣지 않는다.

## 배포와 비용

공개 저장소와 기본 github.io 주소를 이용한 GitHub Pages 배포를 목표로 한다. 별도 유료 서버·데이터베이스·도메인 없이 제공한다. 무료 서비스 정책과 사용량 제한 내에서 운영한다. PWA 설치 및 오프라인 사용은 후속 확장이다.

## 구현 순서와 완료 기준

### 1단계: 프로젝트 준비

- 앱 전용 로컬 Git 저장소
- 기존 추출 JSON과 조사 문서 복사
- 제품 요구사항과 명칭 규칙 문서화
- GitHub 저장소 연결; 브라우저 또는 도구 인증이 필요할 수 있음

### 2단계: 첫 시제품

서판 수집 파밍을 기준으로 목록·상세·용어 설명·개인 복사·폼 편집·자동 저장·JSON 가져오기와 내보내기를 연결한다.

완료 기준:

- 공식 한국어 용어를 확인하고 PoEDB로 이동할 수 있다.
- 서판 수집 파밍의 개인 복사본을 수정해도 기본 자료는 유지된다.
- 새로고침 이후 개인 수정본이 유지된다.
- 내보낸 JSON을 가져와 같은 데이터를 복원할 수 있다.
- 잘못된 입력과 미확인 값을 구별한다.
- 모바일과 키보드로 주요 기능을 사용할 수 있다.

### 3단계: 데이터 확장과 검색·비교

나머지 파밍법 연결, 명칭 설명 보강, 조건 검색과 비교, 공유 가능한 주소, 기본 자료 변경 안내를 구현한다.

### 4단계: 검토와 배포

GitHub Pages 하위 경로에서 앱·데이터·링크가 동작하는지 확인한 뒤 배포한다. 영상 자막 전문이나 개인 데이터를 포함하지 않는다.

## 후속 후보

즐겨찾기, 시즌별 개정 이력, 사용자 제보, 설치 가능한 웹앱, 시세 연동. 첫 시제품의 필수 범위에 포함하지 않는다.
